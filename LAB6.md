# Лабораторная работа № 6

## Условие

Даны константа S и множество точек на плоскости. Точки движутся с постоянными векторами скорости. На каждом шаге анимации необходимо строить выпуклую оболочку алгоритмом Quick Hull. Если её периметр становится больше S, все текущие вершины оболочки меняют свои скорости на противоположные.

## Представление точек и движение

Тип `MovingPoint` содержит четыре числа:

```ts
type MovingPoint = {
    x: number;
    y: number;
    vx: number;
    vy: number;
};
```

`x`, `y` — координаты, `vx`, `vy` — компоненты вектора скорости в единицах координат в секунду.

За интервал Δt положение изменяется по формулам:

```text
x' = x + vx · Δt
y' = y + vy · Δt
```

Между разворотами вектор скорости не меняется, поэтому движение прямолинейное и равномерное. Границы графика служат только областью просмотра: столкновения со стенками не моделируются.

## Выпуклая оболочка

Выпуклая оболочка — наименьшее выпуклое множество, содержащее все исходные точки. Для невырожденного конечного набора это выпуклый многоугольник. Его можно представить как натянутую вокруг точек резинку.

Внутренние точки не являются вершинами оболочки. Точки посередине её прямолинейного ребра также не включаются в список вершин: достаточно концов ребра.

### Определение стороны прямой

Функция `getOrientation(A, B, P)` вычисляет определитель векторов AB и AP:

```text
cross(A, B, P) = (Bx − Ax)(Py − Ay) − (By − Ay)(Px − Ax)
```

- Значение > 0: P слева от направленной прямой A → B.
- Значение < 0: P справа.
- Значение = 0: точки лежат на одной прямой.

Модуль определителя равен удвоенной площади треугольника ABP. Расстояние от P до прямой AB равно:

```text
d(P, AB) = |cross(A, B, P)| / |AB|
```

При фиксированных A и B знаменатель одинаков для всех кандидатов. Поэтому самую далёкую точку можно найти сравнением определителей, без деления и квадратного корня.

### Алгоритм Quick Hull

Алгоритм использует принцип «разделяй и властвуй».

1. Удаляем дубликаты координат из набора, используемого для построения оболочки.
2. Находим крайнюю левую точку A и крайнюю правую B. При равных x сравниваем y. Обе точки принадлежат оболочке.
3. Прямая AB разделяет оставшиеся точки на две стороны. Каждую сторону обрабатываем отдельно.
4. Среди точек слева от A → B выбираем наиболее удалённую от прямой точку C.
5. Треугольник ACB лежит внутри будущей оболочки. Его внутренние точки можно исключить из дальнейшего поиска.
6. Рекурсивно ищем вершины снаружи рёбер A → C и C → B.
7. Если слева от рассматриваемого ребра нет кандидатов, поиск для этого ребра завершается.

Функция `appendSide(a, b, candidates)` добавляет промежуточные вершины цепочки от a до b. Порядок действий:

```text
построить цепочку от A до C
добавить C
построить цепочку от C до B
```

Так вершины сразу попадают в массив в порядке обхода, без дополнительной сортировки. Для второй стороны исходной прямой меняем направление с A → B на B → A, поэтому снова можно искать только точки слева.

Первая вершина в конце массива не повторяется. Замыкание учитывается отдельно при вычислении периметра и построении последнего ребра.

### Почему можно отбрасывать точки

Выпуклая оболочка содержит треугольник, образованный любыми тремя исходными точками. Поэтому точка строго внутри треугольника ACB не может стать крайней вершиной всего множества.

Среди кандидатов слева от AB точка C имеет максимальное расстояние до AB. Дальнейшие вершины этой стороны нужно искать снаружи двух новых рёбер AC и CB. Рекурсия повторяет то же рассуждение для меньших наборов.

### Сложность

При сбалансированном разделении наборов типичная оценка времени Quick Hull — O(n log n). В худшем случае разделения сильно неравномерны и время достигает O(n²). Гарантии O(n log n) для любого входа у этого алгоритма нет.

В данной реализации каждый вызов просматривает кандидатов и создаёт новые массивы через `filter`. Глубина рекурсии в худшем случае линейная; суммарная дополнительная память одновременно сохраняемых массивов может достигать O(n²).

## Периметр

Функция `hullPerimeter` получает вершины H₀, …, Hₘ₋₁ в порядке обхода и складывает длины всех рёбер:

```text
L = Σ |HᵢH₍ᵢ₊₁₎ mod m|
|AB| = sqrt((Bx − Ax)² + (By − Ay)²)
```

Индекс `(i + 1) % m` соединяет последнюю вершину с первой. Длина ребра вычисляется через `Math.hypot(dx, dy)`. Расчёт занимает O(m), где m — число вершин оболочки.

Пример: у прямоугольника с вершинами (0, 0), (4, 0), (4, 3), (0, 3) периметр равен 4 + 3 + 4 + 3 = 14. Добавление точки (2, 1) внутри прямоугольника не меняет оболочку и её периметр.

## Один шаг моделирования

Функция `advancePoints(points, threshold, seconds)` выполняет следующие действия:

1. Перемещает все точки на интервал `seconds` с их текущими скоростями.
2. Строит Quick Hull по новым координатам.
3. Вычисляет периметр новой оболочки.
4. Проверяет строгое условие `perimeter > threshold`, где `threshold` — S.
5. Если условие выполнено, меняет обе компоненты скорости каждой текущей вершины:

```text
vx' = −vx
vy' = −vy
```

6. Возвращает новый массив точек и признак события разворота `reversed`.

Отрицание вектора меняет направление на 180°, сохраняя модуль:

```text
sqrt((−vx)² + (−vy)²) = sqrt(vx² + vy²)
```

Скорости внутренних точек остаются прежними. Для проверки принадлежности вершинам используется `Set` пар координат. Поэтому все точки, совпавшие с вершиной, также разворачиваются, хотя при построении оболочки дубликаты удаляются.

Оболочка строится после перемещения, поскольку за шаг внутренняя точка может стать вершиной, а прежняя вершина — оказаться внутри. Разворот влияет на последующее движение; уже выполненное перемещение не отменяется.

### Особенности проверки порога

- При L = S разворота нет: условие строгое.
- Проверка дискретная: превышение обнаруживается в конце шага, а точный момент достижения S внутри шага не вычисляется.
- Условие проверяется на каждом шаге. Если периметр остаётся больше S, вершины снова разворачиваются на следующем шаге. Это может приводить к колебаниям, особенно если S меньше начального периметра.
- Разворот вершин не гарантирует, что уже на следующем шаге периметр станет меньше S: состав оболочки может измениться.

## Генерация начального набора

`createPoints` размещает точки внутри круга радиуса 4 с центром в начале координат. Для каждой точки независимо выбираются угол положения α и угол направления скорости β в диапазоне [0, 2π).

```text
r = 4 · sqrt(U), где U равномерно распределено на [0, 1)
x = r · cos(α)
y = r · sin(α)
vx = speed · cos(β)
vy = speed · sin(β)
```

Корень в формуле радиуса нужен для равномерного распределения по площади круга, поскольку площадь пропорциональна квадрату радиуса. Угол движения не зависит от угла положения. Все сгенерированные точки имеют одинаковый модуль скорости `speed`, но разные направления. Сам алгоритм шага допускает разные скорости у разных точек.

## Организация анимации в React

Фиксированный шаг моделирования `STEP_SECONDS` равен 1/60 секунды. Браузер вызывает функцию `animate` через `requestAnimationFrame`, но частота этих вызовов может отличаться от 60 кадров в секунду.

Для согласования времени используется накопитель `accumulated`:

1. На первом кадре запоминается время.
2. На следующих кадрах к накопителю прибавляется прошедшее время в секундах.
3. Пока накоплено хотя бы 1/60 секунды, выполняется очередной шаг модели и этот интервал вычитается из накопителя.
4. Неиспользованный остаток переносится на следующий кадр.

На один кадр учитывается не более 0.1 секунды. Это предотвращает длительное выполнение пропущенных шагов после возвращения на вкладку; при большой задержке часть реального времени намеренно пропускается.

### Назначение хуков

| Хук | Использование |
| --- | --- |
| `useState` | Параметры, точки для отображения, запуск/пауза, счётчики |
| `useRef` | Актуальный массив точек для следующего шага без ожидания рендера |
| `useMemo` | Пересчёт отображаемой оболочки, периметра и выражений графика при изменении зависимостей |
| `useCallback` | Сохранение функции `advance` между рендерами, пока S не изменится |
| `useEffect` | Запуск цикла анимации и отмена ожидающего кадра при остановке или удалении компонента |

`pointsRef` нужен, потому что несколько шагов могут выполняться до следующего рендера React. После каждого шага ref сразу получает результат; следующий шаг продолжает именно с него. `setPoints` передаёт результат интерфейсу. Функциональные обновления счётчиков сохраняют все приращения при объединении обновлений React.

Внутри `advancePoints` оболочка строится на каждом шаге модели. Компонент дополнительно вычисляет её для отображаемого состояния: несколько шагов модели могут соответствовать одному обновлению интерфейса.

## Управление

- **Количество точек:** создаёт новый набор; доступно на паузе.
- **Скорость:** меняет модуль скорости существующих точек, сохраняя направления; доступно на паузе. Формула: `v' = v · speed / |v|`.
- **S:** задаёт порог периметра перед запуском; доступно на паузе.
- **Запустить / Остановить:** запускает или приостанавливает моделирование.
- **Один шаг:** выполняет тот же шаг, что и автоматическая анимация, но вручную на паузе.
- **Новый набор:** останавливает движение, создаёт точки и обнуляет статистику.

Синим отмечены вершины оболочки, зелёным — остальные точки. Рёбра краснеют при превышении S. Счётчик разворотов считает события общего разворота, а не число отдельных точек.

## Вырожденные случаи и точность

- Пустое множество: пустая оболочка, периметр 0.
- Одна уникальная точка: оболочка из одной точки, периметр 0.
- Две уникальные точки или все точки на одной прямой: оболочка из двух крайних точек. В реализации принят периметр замкнутого обхода отрезка — удвоенная его длина.
- Совпадающие координаты удаляются только при построении оболочки; исходные движущиеся точки сохраняются.
- Для вертикальных наборов крайние точки выбираются по y при равных x.

Ориентация сравнивается с нулём напрямую, без допуска. Вычисления выполняются в формате JavaScript `number`, поэтому для почти коллинеарных точек возможны эффекты округления.
